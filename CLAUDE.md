# Report Generator — Контекст проекта

## Что это

Веб-приложение для автоматической генерации отчётов разработчика.
Синхронизирует данные из GitLab и Bitrix24, связывает коммиты с задачами,
генерирует нарративные описания на русском языке с помощью LLM,
экспортирует в .docx.

## Документация

- **API-контракт:** `docs/api/openapi.yaml`

## Технический стек

- Backend: PHP 8.2+ / Laravel 11
- Frontend: React (TypeScript) / Vite
- БД: SQLite
- Очереди: Redis + Laravel Queue
- Генерация Word: PHPWord
- LLM: абстракция (Claude API + OpenAI API)
- Контейнеризация: Docker

## Инструменты качества кода

| Слой | Форматирование | Статический анализ                                        |
|------|---------------|-----------------------------------------------------------|
| Backend | Laravel Pint (`vendor/bin/pint`) | PHPStan level 10 + Larastan (`vendor/bin/phpstan analyse`) |
| Frontend | Prettier (`npx prettier --write`) | ESLint (`npx eslint src/`) + `tsc --noEmit`               |

**Обязательно перед коммитом:** `make lint` — проверка без исправлений. `make fix` — автоисправление.

## Правила для всех агентов

1. Код на бэкенде — PHP 8.2+, строгая типизация, Laravel conventions
2. Код на фронтенде — TypeScript strict mode, функциональные компоненты
4. Все API endpoints описаны в директории docs/api/openapi.yaml
5. Русский язык в UI, английский в коде и комментариях
6. Conventional Commits для сообщений коммитов
7. ПОСЛЕ написания кода — запусти Pint/Prettier (форматирование) и PHPStan/ESLint (анализ). Код с ошибками линтера не коммитится

## Паттерны делегирования

Когда задача касается нескольких доменов, используй субагентов:

**Параллельно:**
- Frontend + Backend — когда оба работают по API-контракту
- Два вызова Integration — когда работают с разными API (GitLab и Bitrix24)

**Последовательно:**
- Любой агент → Test Agent (сначала код, потом тесты)
- Integration (парсер) → Integration (движок сопоставления)

**Тесты:** Каждый кодовый агент сам запускает существующие тесты в рамках валидации.
Test Agent нужен ТОЛЬКО для написания НОВЫХ тестов.

**Одно правило:** один файл = один агент. Никогда два агента в одном файле.

- `code-review` — ревью кода на соответствие архитектуре и PRD
